## Positioning rule

The site distinguishes between:

- what has already been built and documented;
- what the demonstrated architecture can reasonably be extended to do.

No client-facing page includes private credentials, Supabase service-role values, API secrets or administrative login credentials.

## Architecture presented publicly

The public portfolio explains the recurring delivery pattern:

GitHub → Netlify / Netlify Functions → Supabase / PostgreSQL / Auth / Storage / RLS → Stripe / Email / Google / external APIs.

This is intentionally presented as a modular environment rather than claiming that every project uses every component.
